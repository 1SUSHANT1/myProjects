Samsung Firmware Security Patch Analysis

About

This project is the other half of the research https://www.sushantadk.com/Projects/A57BootChainResearch.html where I am actively trying to find a vulnerability on the boot sequence of a network-locked, bootloader-locked Samsung SM-A576U which can lead to a untrusted Operating System booting into the system. The other project is my attempt to understand the whole architecture, boot sequence, where things are verified, where transitions happen and form a hypothesis and see if that leads to anything. This one, however is going to be strictly focused on the Samsung's OTA firmware updates and understanding what changed from the last configuration. Maybe a firmware update reveals a flaw I am looking for? But firmware can be patched, so for that reason, the phone will be rarely booted and never connected to a network so it cannot receive any updates.

Sources

Security Updates

Samsung's website at: https://security.samsungmobile.com/securityUpdate.smsb will be used to analyse the security updates released for the phone. Using the general description, I will attempt to reverse engineer it using ghidra and track it down to the individual binaries and locate exactly what changed. Maybe it will lead to an exploit, or just be a reverse engineering exercise.

OTA Updates

Samsung does not provide a direct download portal on it's website where users can manually download the firmware packages. But there are ways to get around it. If you have ever used a GitHub API to do simple things like PUT and GET, it makes sense to just make a request a Samsung phone would make for an update, the servers will send you the package.

But, Samsung doesn't provide an API documentation like GitHub so you'll have figure out a way to communicate with the Samsung Servers, bypass whatever security measures they might have to protect against this, calculate decryption keys, this and that and whatnot and get the package.

We don't have to do all that ourselves because my friends(really?) at: https://github.com/topjohnwu/samloader-rs have already figured it out and we can just use their tool to get the newest updates! Yay!

Samloader and Ghidra

Samloader: https://github.com/topjohnwu/samloader-rs

Installing samloader is easy. Following the instructions, you need a working rust toolchain, which you can install as:


sudo apt-get install rustup
rustup default stable

This will install the components we need including cargo. Then we use cargo to install samloader like:


cargo install samloader

The tool will now be at /home/user/.cargo/bin/samloader. You can edit your path to include this, or just move the tool to your working directory and execute it there. I chose the later. Running help command on the tool reveals that you download the packages as follows:


samloader download --model DEV_MODEL --region DEV_REGION

That's it! and when it is done, you'll get a package like this: SM-A576U_1_20260907163110_1dajb2p9zd_fac.zip. Since this is going to disappear in a month, I am going to create a copy of the file, and work on the copy and leave this one untouched. Let's load something in Ghidra. First, you have to select the language for whatever file you want to analyze. I followed this link: https://source.android.com/docs/compatibility/cdd, and according to it, the setting should be as follows:

  • Processor: AARCH64
  • Size: 64
  • Endian: Little

And the cores used on the phone are built on ARMv9-A architecture. But Ghidra didn't have this one. Doing some more research, I figured ARMv9-A and ARMv8-A are backwards compatible, and selecting the v8A variant and default compiler, I got:

Old firmware verification

I am using samfw.com to get the firmware that I am missing. And turns out, I was wrong about how many firmware I actually missed. The release dates and bootloader revision numbers are as follows:

  • 2026-07-05 SW REV: 1
  • 2026-08-05 SW REV: 3
  • 2026-09-05 SW REV: 4

The firmware released on 09-05 is the current release so I used samloader to get the firmware directly from the Samsung servers, and compared the hash with the firmware on the archive. The hashes matched! so I have a reasonable belief that this website is indeed uploading the correct firmware and not some generic ones.
